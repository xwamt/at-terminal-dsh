### 0.4 任务 DoD（每个任务共用）

1. **代码 + 测试同时提交**：至少覆盖正常路径、边界、失败路径；测试必须能反向失败（临时改坏一处 → 精确 FAIL → 改回）。
2. **四项开工门禁全绿**，且没有新增 `skip` / `only` / 静默 catch。
3. **没有新增 `@deepseek-ai/*` 裸导入到 `src/**`**；没有新增字面色；没有改动 `webview/**`（base 变体共用区）。
4. **模型可见行为**（工具描述、提示词段、错误文案）用 `at_terminal_ping` / `ctx.tools.schemas` / 单元测试核对真实生效值，不能用源码推断。
5. **文档同步**：`README.md`、`dsh/README.md`、`docs/features*.md`、`docs/releases/*.md` 中与被改行为相关的表格/数字同步更新；`test/docs` 门禁必须通过。
6. **构建产物同步**：`npm run build` 后 `dsh/scripts/verify.mjs` 的 `--check` 必须报告产物与源码一致；不得只改源码不改 bundle。
7. **无法验证的项**：在任务末尾写“未验证 + 原因”，不得写成完成。

### 0.5 执行流程（每个任务的标准动作）

1. **读**：读任务列出的所有文件和对应测试；读上游研究报告对应段落。
2. **写前确认**：确认该文件当前没有其它任务在改；确认接口真实存在（§0.3 / 上游报告的接口矩阵）。
3. **实现**：只做任务范围内最小改动；新增可选参数或新工具，不改变旧契约。
4. **补测试**：先写失败用例（红），再实现（绿），再做反向测试（改坏 → 预期 FAIL → 改回）。
5. **单任务验证**：跑该任务的 targeted tests，再跑 `npm run typecheck`；涉及工具/设置/提示词时跑 `npm run verify:dsh`。
6. **全量验证**：每个里程碑结束或每 3 个任务跑一次 `npm test` + `npm run verify:dsh` + `npm run verify:kernel`。
7. **记录**：更新本计划任务状态（`待执行` → `进行中` → `已完成`），记录命令、输出摘要、未验证项；commit message 使用 `feat|fix|docs(scope): ...`。

### 1.1 目标

### 1.2 非目标（本计划明确不做）

| 不做 | 原因 |
|---|---|
| 把 AT Terminal 改造成 `ctx.fs` / `ctx.subprocess` 远程 provider | DSH 0.2.2 没有随包发布 SSH provider；`ctx.fs`/`ctx.subprocess` 是单例，和插件的多服务器资产模型冲突；详见上游报告 §P3 |
| 重写自建 HTTP 通道为 Typert Remote | `ctx.remote` 依赖构建期生成的严格 codec，跨 rc 不稳定；0.3.0 已有 Host/Origin/content-type 围栏 |
| 把 `dsh-session-projections` 用于实时连接/传输状态 | projection 从已提交 Session 事件日志折叠，和实时 SSH 状态不是一类数据 |
| 把 `dsh-client-ui-sidebar-documentpreview` 直接用于远程 SFTP | 它依赖 Session workspace 的 `workspaceFiles.read/readBytes` 资源地址，远程 SFTP 没有对应地址；只借鉴布局 |
| 把 `dsh-tool-fs` 的 `apply_patch` / `dsh-tool-str-replace-editor` 直接当远程工具 | 它们只操作本地 `ctx.fs`，无法到达 SSH 服务器 |
| 为 `settings.section.icon` 把设置页改成顶级 `settings.section` | 当前设置入口是 `settings.plugins.tab`；改成顶级页会重复入口 |

## 6. M3：0.5.0 可选能力（A1–A2）

### A1 远程 `at_terminal_sftp_apply_patch`（opt-in）

- **优先级/估算**：P2 / M–L（3–5d，待 R1/R2 稳定后）
- **目标**：用 Codex 风格 patch 一次修改多个远端文件；默认关闭，按配置启用。
- **依据**：DSH 0.2.2 新增 `apply_patch`（默认关闭）；`@deepseek-ai/dsh-fs-patch` 提供 `parsePatch` / `applyHunks`（纯函数，npm 0.2.2-rc.1）；`dsh-tool-fs` 的 apply-patch 是“全量预检 → 顺序提交 → 失败保留已知部分”。
- **实施步骤**：
  1. 依赖：在根 `package.json` 增加 `@deepseek-ai/dsh-fs-patch@0.2.2-rc.1`（精确版本）并加入 `dsh/scripts/vendor.mjs` 的 `VENDORED`（或构建期 inline），在 `verify.mjs` 的 deps 白名单中加入；保留其 MIT/Apache-2.0 attribution。
  2. `SftpAgentService.applyPatch`：按 patch 操作顺序预检每个路径（stat/read、二进制/大小、hunk 匹配）；`parsePatch` / `applyHunks` 只处理 LF，EOL 由服务层按文件检测并恢复。
  3. 提交：按 R1/R2 的 `editFile` / `writeFile` / `deleteFile` / `rename` 顺序执行；每步授权；返回 `phase`、`operations[]`（completed/failed/unknown/skipped）与 `affectedPaths`；首个失败停止并保留前序结果。
  4. 工具定义 `at_terminal_sftp_apply_patch`：`serverId?`、`path`（基准目录）、`input`（Codex patch），默认 `enableApplyPatch: false`；启用后才注册（可用配置条件）。
  5. 文档明确：远程 patch 不进 DSH Review；仅在工具 `output.render` 显示摘要。
- **DoD**：单文件 Add/Update/Delete/Move 各 1 例；多文件 patch 预检失败时零写入；部分提交失败时返回每项状态；CRLF/二进制/超大文件拒绝；工具默认关闭且开启前 schema 不出现。
- **测试/验证**：`test/agent/SftpAgentService.test.ts`（≥10 例）、`test/dsh/tools.test.ts`、`test/docs/toolTable.test.ts`、`npm run verify:dsh`。
- **风险/回滚**：SFTP 无事务；`dsh-fs-patch` 只支持 LF 归一化；vendor/license 成本；如收益不足可删除工具定义，服务方法保留内部使用。

### A2 可选 bundle 安装诊断与插件详情

### 11.2 计划偏差与说明

1. **A1 依赖实现方式**：计划原文允许“vendor 或构建期 inline”。由于 §0.1 约束 1 要求 `src/**` 不得 import 任何 `@deepseek-ai/*`（`verify:kernel` 会硬失败），实际采用研究报告 P2-1 明确允许的 fallback：把 `@deepseek-ai/dsh-fs-patch@0.2.2-rc.1` 的 `parsePatch`/`applyHunks` 源码语义移植到 `src/sftp/patch/`，保留 MIT + OpenAI Apache-2.0 许可与 NOTICE，不新增运行时依赖。
2. **U1 兼容策略**：`menuFocus.ts` 的旧自绘菜单保留作为 0.2.1/旧宿主 fallback（计划风险表允许）；新宿主走 `ctx.contextMenus`。
3. **docs/releases/0.3.1.md–0.3.5.md** 为仓库历史发行说明（VS Code 基线），本次未改写；DSH 侧兼容声明已按 C3 更新 `docs/releases/0.3.0.md` 的宿主版本行。
4. 版本号未提升、未执行 `npm run release -- --publish`：本任务只执行优化实施，发布动作需维护者按 §7.4 决定版本与时机。
