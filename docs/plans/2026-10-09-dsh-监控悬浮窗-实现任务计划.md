> 分支：`main`（新特性分支推荐：`feat/dsh-monitor-floating-window`）  
> 日期：2026-10-09  
> 宿主：DeepSeek Harness (DSH) Web / Desktop `0.1.7-rc.2+`  
> 上游调研：本轮官方接口与架构深度调研（基于 `cordis-plugin-development`、`references/practices.md`、`references/user-actions.md`）

## 1. 悬浮窗架构方案与交互蓝图

### 1.1 双层悬浮窗设计（DockKit 原生浮窗 + 全局 HUD）

为兼顾“详细指标深钻分析”与“轻量常驻概览感知”，设计两套相辅相成的悬浮窗形态：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ DSH 页面总览 (AppFrame)                                                      │
│                                                                             │
│ ┌─────────────────────────────────────────────────────────────────────────┐ │
│ │ 顶层全局浮层槽位 (shell.overlay) - 适合常驻与轻感知                       │ │
│ │   ┌──────────────────────────────┐                                      │ │
│ │   │  常驻 HUD 迷你监控挂件       │ ◄── 贴边停靠、可折叠、脉冲指示灯      │ │
│ │   │  - CPU: 24% | MEM: 62%       │ ◄── 点击展开卡片或一键激活大浮窗      │ │
│ │   │  - Agent: 执行命令中 (3s)    │                                      │ │
│ │   └──────────────────────────────┘                                      │ │
│ └─────────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
│ ┌──────────────┬──────────────────────────────┬───────────────────────────┐ │
│ │ 左侧导航栏   │ 中部会话流 (Conversation)    │ 原生 DockKit 浮动监控大窗 │ │
│ │              │ - corner 槽位 [📊 监控图标]  │ ┌───────────────────────┐ │ │
│ │              │ - composer 吸顶监控胶囊      │ │ 资产硬件 / Agent 执行 │ │ │
│ │              │                              │ │ 独立窗口 (可任意拖拽、│ │ │
│ │              │                              │ │ 八向缩放、Dock吸附、  │ │ │
│ │              │                              │ │ Esc关闭)              │ │ │
│ │              │                              │ └───────────────────────┘ │ │
│ └──────────────┴──────────────────────────────┴───────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 形态 A：DockKit 原生浮动大窗（`DockKit Floating Pane`）—— 主力沉浸面板
- **依托接口**：`ctx.sidebarRightTabs.register` + `ctx.sidebarRight.float(tabId, rect?)`
- **特性**：
  - 拥有 DockKit 原生拖拽移动（Drag header）、边缘缩放（Resize）、Dock 还原吸附、全屏切换与关闭按钮；
  - **脱离侧边栏独立渲染**：根据官方规范（`ui-sidebar-right/README.md`），即使右侧栏处于折叠状态，已浮动的面板依然会常驻渲染在视口顶层；
  - **位置持久化**：窗口尺寸和坐标自动保存在 `localStorage` (`dsh.sidebar-right.v1.<sessionId>`)，刷新后还原。

#### 形态 B：全局 HUD 悬浮小窗（`shell.overlay` 槽位）—— 轻量常驻感知
- **依托接口**：`ctx.slots.inject('shell.overlay', () => ctx.slots.register(...))`
- **特性**：
  - 挂载在 `.overlayLayer`（`position: absolute; inset: 0; z-index: 20; pointer-events: none`），子元素 `pointer-events: auto`；
  - 微缩悬浮球 / 胶囊（Mini HUD），支持贴边吸附和折叠展开；
  - 提供 CPU/Mem 健康环形灯与 Agent 执行状态指示波纹。

## 2. 功能详细设计规格

### 2.1 资产硬件信息监控（Asset Hardware Info Monitor）

1. **核心监控项**：
   - **CPU**：总体使用率（%）、单核分布条、1/5/15 分钟 Load Average。
   - **内存**：物理内存（Total / Used / Free / Cached）、Swap 使用百分比。
   - **磁盘**：根分区 `/` 及挂载数据盘使用率（`df -h`）、IO 读写简况。
   - **网络**：实时 Rx / Tx 吞吐率（KB/s、MB/s）与流量走势图。
   - **进程**：消耗最高的 Top 5 进程（PID, User, %CPU, %MEM, Command）。
2. **采集策略与性能守卫**：
   - 由 Host 侧按需触发（通过现有的 SSH 会话管道执行无副作用轻量读取 `/proc/stat`、`/proc/meminfo`、`vmstat`）；
   - 采集频率：活跃可见时 3s 一次；浮窗关闭或折叠时**立即挂起**，杜绝无意义消耗；
   - 错误降级：目标机不支持 `/proc`（如特定嵌入式或 macOS 主机）时，优雅回退到通用的 `top -b -n 1` / `uptime`。

### 2.2 Agent 执行监控（Agent Execution Monitor）

1. **核心监控项**：
   - **正在执行的指令（Live Action）**：
     - 当前命令预览（关键敏感信息经 `redaction` 脱敏）；
     - 运行计时器（实时毫秒级秒表）；
     - 状态徽章：`RUNNING`（蓝色脉冲动画）、`CONFIRMATION_WAITING`（橙色等待用户确认）、`SUCCESS`（绿色）、`DENIED`（红色阻断）；
     - 实时终端输出微缩流（stdout / stderr 字符流滚动窗）。
   - **安全策略与审计流水（Audit Stream）**：
     - 接入现有的 `AgentAuditLog`，展示最近 10 条远程操作记录；
     - 包含信任分级决策（Trust 自动放行 / 白名单 / 高危拦截原因）。
   - **传输监控（SFTP Active Transfers）**：
     - 展示后台正在进行的 SFTP 上传/下载任务列表、进度条（百分比）与传输速率。

## 3. 分阶段实施任务清单

### 阶段 0：基础设施与契约定义（Phase 0: Foundation & Contracts）

- [ ] **T0.1 协议与类型定义**
  - 在 `src/platform/dsh/client/models.ts` 及 Host 侧定义监控通用数据类型：
    - `HardwareMetrics`（CPU, Mem, Disk, Net, Load, Processes）
    - `AgentExecutionSnapshot`（当前任务、命令详情、审计历史、传输进度）
    - `MonitorControlMessage`（SSE 动作指令：open, close, focus, set-target）
- [ ] **T0.2 Host 侧 Agent 监控工具注册**
  - 在 `dsh/tools.js` 增加原生 Agent 工具定义：
    - `at_terminal_open_monitor`：入参 `{ target: 'hardware' | 'agent_execution', serverId?: string, mode?: 'float' | 'hud' }`
    - `at_terminal_get_hardware_metrics`：Agent 主动查询当前指标供大模型决策使用
    - `at_terminal_get_agent_execution_status`：查询当前 Agent 任务执行快照
- [ ] **T0.3 Host 侧通道路由与 SSE 广播机制**
  - 在 `dsh/channel.js` 的 `POST /dsh-at-terminal/rpc` 增加监控相关 RPC：

  - 增加广播辅助函数 `broadcastMonitorEvent(event, data)`，通过现有的 `PREFIX/events` (SSE) 推送至客户端。

## 4. 交付物验收标准（Definition of Done）

1. **Agent 唤起验证**：
   - 模型调用 `at_terminal_open_monitor` 后，DSH 界面能毫秒级弹出对应主机的原生浮动窗口，或点亮 HUD 监控悬浮小窗，工具返回成功确认。
2. **用户交互验证**：
   - 用户点击资产卡片上的监控按钮或按下 `Mod+Shift+M`，浮窗正常唤起，可拖拽、缩放、还原 Dock 或关闭。
3. **监控数据保真**：
   - 资产硬件监控：真实反映目标机 CPU/Mem/Disk 指标，目标机断开或无权限时显示优雅错误态；
   - Agent 执行监控：实时与 Agent 任务同步，直观展示正在执行的指令流与审计放行/拦截状态。
4. **代码与宿主兼容**：
   - 严格遵守 DSH 官方规范，零 `@deepseek-ai/*` 客户端裸导入，全量复用宿主语义 CSS 变量，浅色/深色主题自适应良好。
