# dsh 客户端视觉回归清单（2026-10-07）

> U0–U4 每轮都以「用户看一眼界面」收尾。这些看过的点此前只散落在提交信息和对话里，没有可重跑的凭据：下次改动后没人知道该复查什么。本清单把它们固化下来。
>
> **本文档不是验收报告。** 它是下一次改动后要重跑的待办。每项都写了「怎么看」和「期望看到什么」，以及**谁确认过**——没确认的项明确标成待确认，不假装已验。

## 怎么用这份清单

- **每次改动 dsh 客户端 UI 后**，按 §2 逐项过一遍。改动只碰某些文件时，只跑受影响项——每项都标了触发条件。
- **`[自动]` 项**跑 `node dsh/scripts/check-visual-invariants.mjs`（纯静态，秒级）。它的 PASS 只证明结构在，**不证明好看**。
- **`[需真机]` 项**必须人眼在真实 dsh 里看。脚本替代不了——本文档存在的主要原因就是这些项脚本查不了。
- 勾选框留空。**只有真机看过才能勾**。

### 标注含义

| 标注 | 含义 |
|---|---|
| `[自动]` | `check-visual-invariants.mjs` 能查（结构层面） |
| `[需真机]` | 必须人眼看，脚本查不了 |
| `[已确认]` | 2026-10-07 用户已看过并认可 |
| `[待确认]` | **没有证据说已确认**，需真机走查 |

### 结构性不变量（与真机观感无关，脚本可查）

这四条原本全靠人眼发现有错，现在有门禁。它们和 §2 的项一一对应：

| 不变量 | 门禁项 | 对应清单项 |
|---|---|---|
| 桥接层无字面 fallback | `verify.mjs` 的 `theme-tokens`（**第 9 项，不在本脚本内**） | 1 |

> **关于桥接层那条**：它已由 `verify.mjs` 第 9 项（`theme-tokens`）把守，**故意不在** `check-visual-invariants.mjs` 里重写一遍。同一规则写两份会漂移，然后两份对「什么叫 fallback」产生分歧。本脚本只断言那道门禁**还在**（`bridge-gate` 项）——一个指向已消失门禁的引用比没有门禁更糟，因为它看起来像有覆盖。
>
> 所以：**桥接层裸色查 `npm run verify:dsh`，不查本脚本。**

## 2. 清单

### 1. 明暗主题（light / dark 各走一遍）

- **验证方式**：`[需真机]` · **`[已确认]`** 2026-10-07
- **触发**：改 `styles.ts` 的 `TOKEN_BRIDGE`、任何 `--vscode-*` 桥接项、或 token 覆盖面。

**怎么看**

1. 在宿主里切到**浅色**主题（U0 删掉了 32 个深色 fallback，这是首要风险面）。
2. 三个页面各停一遍，逐个看：**SFTP 树** → **终端** → **服务器表单**（新增/编辑一台服务器，表单里的输入框、下拉、开关）。
3. 再切回**深色**，同样三个页面走一遍。

**期望看到什么**

- 无低对比度：任何文字与背景都读得清，不需要眯眼。
- 无错色：没有「本该是浅色系却是深灰」的残留（U0 前 fallback 造成的典型症状）。
- 三页面在两个主题下观感一致——不是「都能看」，是**没有哪个元素只在其中一个主题下不对劲**。
- 表单的 focus 环、下拉箭头、开关滑块在浅色下都可见（这些容易漏，因为深色下它们天然够亮）。

> **这条为什么排第一**：U0 之前 32 个 `--vscode-*` 声明带深色字面 fallback，浅色主题下会留下错色。已由 `verify.mjs` 第 9 项守住「桥接层不再有 fallback」，但**门禁只能保证源码里没有字面色，保证不了实际渲染够不够对比**——那部分仍要人眼。

### 2. 终端对比度

- **验证方式**：`[需真机]` · **数值 `[已确认]`**（WCAG 实测，`contrast.ts` 单测钉住）· ⚠️ **色感 `[待确认]`**
- **触发**：改 `webview/terminal/theme.ts`、动 ANSI 配色、或换浅色/深色背景。

**怎么看**

1. 连一台服务器，让终端渲染**同时用到前景色系与背景色系**的内容（`ls` 彩色输出、`git diff`、带语法高亮的文件）。
2. 用取色器（或 DevTools）测三组：**普通文字 / 背景**、**光标 / 背景**、**最暗的前景色**（`black`、`brightBlack`）。
3. 对比数值：文字 **≥ 4.5:1**，光标 **≥ 3:1**。

**期望看到什么**

- 文字 ≥ 4.5:1，光标 ≥ 3:1。U2 已用 WCAG 相对亮度校正过，背景实测 `#101820`：

| 颜色 | 校正前 | 校正后 | 说明 |
|---|---|---|---|
| `black` | `#000000`（1.2:1） | **`#808080`**（4.5:1） | 黑已无色相可保，退灰阶 |
| `brightBlack` | `#666666`（3.1:1） | **`#808080`**（4.5:1） | 同上 |
| `red` | `#aa0000`（2.3:1） | **`#ff0707`**（4.5:1） | 提亮但保持色相——仍是红 |
| 其余 16 色 | — | **字节不变** | 已达标即原样返回 |

- ⚠️ **两个色相仍需肉眼确认**（数值达标 ≠ 色感可接受）：
  - **`#808080` 的灰**——`black` 和 `brightBlack` 被迫退到同一个灰阶。数值上 4.5:1 达标，但**深灰取代纯黑**在深色背景上是否显得「发灰、有雾」，需要人眼看一眼是不是可接受。
  - **`#ff0707` 的红**——U2 明确选择「保色相优先于拉白」：报错红 `#ff0707` 比 `#aa0000` 亮很多，视觉上可能偏「霓虹」。**确认它仍读作红色，而不是刺眼的荧光色**。
- `theme.ts` 是 **base 变体共用区**（`test/webview/TerminalTheme.test.ts` 守着）。任何改动后 `package:base` + `package.baseBundle` 必须仍绿。

> **`theme.ts` 是红线文件。** 改它会同时影响 base 变体，U2 因此要求新逻辑放独立模块（`contrast.ts`），`theme.ts` 只调不实现。别在 `theme.ts` 里直接写算法。

### 3. 状态栏路径（长路径保尾部、左侧淡出）

- **验证方式**：`[自动]` `statusbar-path` + **`[需真机]`** · ❌ **`[待确认]`**
- **触发**：改 `shared.ts` 的 `pathLabel()`、`styles.ts` 的 `.att-dir*`、或在 `.att-dir` 和它的两半之间插入任何元素。

**怎么看**

1. `cd /root/.m2/repository`（或任何长路径），让 SFTP 根路径变长。
2. 看状态栏那一行；再把右侧栏拖窄，逼出溢出。

**期望看到什么**

- **保留尾部**（`repository/...`），**左侧淡出**——被砍掉的应该是 `/root/.m2/`，不是尾部的长文件名。
- **浅色主题下渐隐是否自然**：U3 的新做法，**这是本次最该盯的一项**。mask 只读 alpha，所以渐变起点用 `currentColor`；重点看有没有「灰底上灰字」的突兀边界，或渐变范围过大（吃掉整条路径）过小（看不出在渐隐）。
- 悬停显示**完整路径**；`title` 在 `.att-dir` 上、不在任何半截上。
- 短路径**不付渐隐的代价**（`data-at-terminal-path-truncated="false"` 时无 mask）。

> **结构门禁查了什么、没查什么**：门禁保证两半都存在、都有样式、且**都是 `.att-dir` 的直接子元素**——因为 `.att-dir > * { flex: 0 0 auto; }` 是子选择器，只够到直接子元素。**把两半包进一个 `<div>` 分组，规则悄悄失效，不报错，渐隐悄悄死掉。** 门禁抓得到这种包一层，但抓不到「渐变长度 30% 好不好看」——那只能人眼看。

### 4. SFTP 失败行（树内一行，不清空兄弟）

- **验证方式**：`[需真机]` · ❌ **`[待确认]`**
- **触发**：改 `sftp.ts` 的 `renderFailure` / `models.ts` 的 `flattenSftpTree`、`sftp.*` i18n key、或 SFTP 失败码分流。

**怎么看**

1. `chmod 000` 某个子目录（需要 root，所以直接在服务器上做）。
2. 回到文件树，**点那个目录**。
3. 然后把权限改回去，刷新。

**期望看到什么**

- 失败目录渲染成**树内一行**，不是整页失败横幅（U3 的修复点——原先页面级的 `att-banner` 被内联进树里，一个目录读不到看起来像整页炸了）。
- 这一行：**⚠ 图标** + **本地化句子** + **一个真 `<button>` 重试**。文案按码分流：
  - `sftp-no-such-file` → 「这一层不存在」
  - `sftp-permission-denied` → 「当前登录账号没有读取它的权限」（U3 实测渲染值）
  - `sftp-read-failed` → 通用读失败
- **兄弟目录仍在**——失败只插一行，不清空同级和根。
- **不显示后端 `message` 原文**（它会暴露别人机器上的路径）。原始 code 只走 `data-at-terminal-sftp-code` + `title` 供排障。
- 父目录行的 `aria-expanded`、展开箭头、键盘折叠**全部照旧**——只有那一行变了。
- 失败行**插在中间**（按目录顺序），不跳到顶部也不沉底。

> **已知缺口（如实登记）**：**没有截断标志位**。`channel.js` 的 `sftp.list` 无上限参数、`DshSftpListing` 无截断字段、`src/sftp/` 全目录搜 `truncat|MAX_|maxEntries` 只命中上传字节校验。按官方做法应以一条标记收尾，但 Host 侧没有这个语义 ⇒ U3 跳过，未编造。**这条不许在清单里假装已实现。**

### 5. 空态出路

- **验证方式**：`[自动]` `empty-state-exits` + **`[需真机]`** · ✅ **`[已确认]`**
- **触发**：删改 `sftp.ts` 里 `sftp.noTerminal` / `sftp.disconnected` 的渲染块，或任何「看着像纯文案改动」的 `sftp.ts` 重构。

**怎么看**

1. 未连任何终端时打开文件页 → 看「无终端」空态。
2. 连上 → `exit` 掉远端 shell（或手动断网）让终端断开 → 看「已断开」空态。

**期望看到什么**

| 空态 | 必须有的出路 | 按钮去哪 |
|---|---|---|
| 无终端（`sftp.noTerminal`） | 「去终端页」按钮 | 切到终端页（复用 `mode.terminal` 标签文案） |
| 已断开（`sftp.disconnected`） | 「重连」按钮 | 重新读目录（复用 `terminal.reconnect`） |

- 两个按钮**各自都在**，不是同一个共用块——门禁按字符串逐个查，因为一次重构可能只删掉一个。
- **零新增 i18n key**：复用已有 key，所以切换中英文时按钮文案跟着变。

> **为什么这条重要**：一个空态如果说了「去终端页连接一台服务器」却给不出按钮，那是**有解释无出路**——比什么都不说更糟，因为它看起来已经回答了问题。
>
> `disconnected` 的按钮调的是**重读**（`onRefresh`），不是真的重连：插件没有从这个页面重连会话的 RPC，重连归终端页。诚实的做法是重问服务器，让答案自己回来。**断线时保留屏幕、不展示传输内部错误**，对齐官方 `sidebar-terminal` 的做法。

### 6. 页内导航快捷键

- **验证方式**：`[需真机]` · ❌ **`[待确认]`**
- **触发**：改 `main.ts` 的快捷键注册、`dsh/package.json` 的 `inject`、或宿主的 shortcuts 服务。

**怎么看**

1. 打开 AT Terminal 面板（任意页面），焦点**在面板内**。
2. 依次按 **`Cmd+Alt+1`** / **`Cmd+Alt+2`** / **`Cmd+Alt+3`**。
3. 再按 **`Mod+/`**（macOS 是 `Cmd+/`）打开官方速查面板。

**期望看到什么**

- 三条命令分别切到 **资产 / 文件 / 终端**页。
- 速查面板里**自动列出这三条**（不需要插件自己再弹一次提示——宿主会显示有效快捷键）。
- 按键**透传**：切到终端页后按 **`Ctrl+C`**、`Ctrl+D` 等，必须到达终端，不被面板截走。
- 已在目标页 / 表单打开中 → **静默空操作**（不重复跳转、不丢表单内容）。
- 焦点**不在面板内**时 → **交还浏览器**，不抢。

> **键位不是字符串**。宿主读 `{ code: 'Digit1', modifiers: ['primary','alt'] }`（`KeyboardEvent.code`），写 `'Mod+P'` 会被 `Unsupported shortcut code` **拒绝**。
>
> **Linux 必须不绑定**：从 `defaults` 省略该平台（官方 `files`/`terminal` 同样省略 `web:linux`）。写了会**直接 throw 导致插件加载失败**——Linux Web 只放行三个键且已被官方占满。
>
> **走点击 nav 按钮而非 `setMode`**：`mode` 是 `body.ts` 里的 React state，无服务发布；`changeMode` 还做两件事（latch 首次 SFTP 访问 + 触发 reload），裸 `setMode` 会跳过。
>
> 单测只能证明「终端页 Ctrl+C 不被截走」，**证明不了真实键位在不同系统上对不对**——这是待确认的根本原因。

### 7. 图标（server 机架 / file·folder 底板）

- **验证方式**：`[自动]` `icons-aria` + `icons-color` + **`[需真机]`** · ❌ **`[待确认]`**
- **触发**：改 `client/icons/` 下任何文件、或新增图标。

**怎么看**

1. 看**三处**：SFTP 树行首、导航（工具栏分段切换）、失败行的重试按钮。
2. 侧栏尽量拖窄，缩到接近最小可视宽度。
3. 切浅色 / 深色各看一次。

**期望看到什么**

- **16px 下 `server` 双层机架是否够清楚**——两层 12×4.5 的圆角矩形、2px 间隙。间隙是让它读成「两台」的关键；单框加横线会读成「一个盒子里有条线」。**在 16px 下间隙还在吗？**
- **file / folder 底板对比是否够**——`file` 的 sheet 用 `--dsw-alias-label-secondary`、折角用 `label-dimmed`（深一档）。sheet 应读成主平面、折角读成背光面。
- 深浅两主题下底板都**不与行背景糊在一起**。
- 图标与文字**基线对齐**，大小不显得突兀。

> **结构门禁查了什么**：12 个导出字形**全部经 `frame.ts` 的 `lineIcon()`/`plateIcon()`**（两个 builder 都设了 `aria-hidden`），且 `icons/` 下**零字面色**（hex 与 `rgb()/hsl()` 都算）。
>
> **门禁抓不到「像不像」**：`#808080` 的灰在 16px 机架上读不读得出「服务器」，是纯观感。抄录自官方 primitive 的几何**不等于**在这个尺寸读得出来。

### 8. 断点（右侧栏 < 480px）

- **验证方式**：`[需真机]` · ❌ **`[待确认]`**
- **触发**：改 `styles.ts` 的 `@container att-panel (max-width: 480px)` 块、工具栏、或状态栏。

**怎么看**

1. 拖右侧栏宽度**从宽到窄，缓慢拖过 480px**，在临界点两侧各停一下。
2. 重点看**服务器列表工具栏**（最宽的一个：导航 + 四个带文字按钮）和状态栏。
3. 打开一个右键菜单（`.att-menu`）。

**期望看到什么**

- 工具栏**换行**且**不重叠**——文字和按钮不叠在一起。
- 状态栏 **chip 不被挤没**（路径让位给计数，计数必须还在）。
- **`.att-menu` 不被拖走**——菜单跟随光标，不偏到面板左边或右边。
- 文字**保持 12px**，按钮**保留文字标签**（标签是区分相邻按钮的唯一信息；缩小字号等于把换行问题换成可读性问题）。

> **断点用 `@container` 而非 `@media`**——变窄的是**侧栏**，不是窗口。用 `@media (max-width)` 会在窗口宽但侧栏窄时不生效。
>
> **且 `container-type` 放在 `.att-page` 而非 `.att-root`**：`container-type` 隐含 layout containment，会让元素成为定位后代的包含块，而 `.att-menu` 是 `position: fixed` 用视口坐标——放 root 上菜单会被面板偏移拖走。**这是本项最容易被"顺手改回去"的地方。**
>
> **`480px` 是本插件自己的判断，不是官方数值**（Harness 未发布第三方面板的断点，从服务器列表工具栏实测约 470px 得来）。U4 提交记录明写「待实测的首次猜测」。**拖窄看一次就是在校准这个数**——觉得不合适就改，但要改注释里的理由。

### 9. 键盘可达（SFTP 树 / 弹窗）

- **验证方式**：`[需真机]` · ✅ **逻辑 `[已确认]`**（单测断言键盘与鼠标结果一致）· ⚠️ **焦点环样式 `[待确认]`**

2. 打开一个弹窗，`Esc` 关掉。

**期望看到什么**

| `Tab` | 能进 SFTP 树；可展开行 `tabIndex=0` |

### 10. reduced-motion 降级

- **验证方式**：`[自动]` `reduced-motion` + **`[需真机]`** · ✅ **`[已确认]`**
- **触发**：改 `styles.ts` 的 spinner、`@keyframes`、或新增任何动画。

**怎么看**

1. macOS：系统设置 → 辅助功能 → 显示 → 减少动态效果 → **开**。
2. 触发一次 pending 态（快速读一个慢目录，让旋转点出现）。
3. 对比开 / 关两种状态。

**期望看到什么**

- 减少动态效果**开启时**：旋转点变成 **6px 静态点**——**不是变暗的环**。
- 减少动态效果**关闭时**：正常旋转。
- 文字仍照常出现（动画降级**不等于**隐藏 loading 文案）。

> **为什么是静态点而不是暗环**：6px 的环和噪点无法区分，而实心点仍读作「进行中」——这是官方 reduced-motion 约定保留的静态底色。暗环在那个尺寸下**仍是一个动画提示**，只是更不明显。
>
> **opacity 阈值故意不动**：淡入不是动效，去掉它反而会把这个 class 存在的意义（压制快读闪烁）打掉。
>
> **门禁查的是「块存在」且「块内确有让动画停掉的声明」**——一个存在但里面什么都没写的块，等于把意图记下来而让 spinner 继续转，门禁必须抓这种。
