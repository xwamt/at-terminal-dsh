## 怎么用这份清单

- 计划里每个视觉任务（UI2-05…UI2-12）的 DoD 都引用本文档。**改动 ui 后按类走查**，只走受影响的行。
- 两类标注：
  - `[自动]` —— 静态断言能查（`className audit`、token 字符串、`em dash`/emoji grep）。PASS 只证明规则存在。
  - `[需真机]` —— 必须人眼在真实 dsh 里看。这份清单存在的主要理由就是这些项脚本查不了。
- **勾选框留空。只有真机看过才能勾。**
- 每一行都要写「怎么看」和「期望看到什么」——没有期望的勾选等于没看。

## 10. 2026-10-18 首次真机走查（at-pc 远程取证，`bdec116`）

**方法**：本机起 `at-pc-server` + `at-pc-agent`（device_id `atpc-ui-verify`），MCP 驱动
`list_windows` / `focus_window` / `capture_screen` / `read_screen_text`，窗口是
`at-terminal-dsh 界面优化建议 — DeepSeek Harness`（hwnd 21610，1472×820 逻辑点，scale 2.0）。

**证据图**（`docs/research/2026-10-18-ui-walkthrough-assets/`）：
`panel-top.jpg`（面板整体）· `toolbar-icons.png`（工具栏图标）· `tab-chip.png`（tab 图标）·
`d1-row-actions-over-badge.png`（D1 缺陷特写）· `d2-gauge-old-vs-new.png`（D2 新旧对比）。

**坐标口径（踩过，记下来）**：`list_windows.rect` 与 `get_ui_tree` 是**逻辑点**；
`capture_screen.crop`、`read_screen_text` 行框、`mouse_click` 期望的是**物理像素**——
乘 `scale_factor`。把逻辑点直接喂 crop 会截到左上角一块无关区域。

**已验（截图/OCR 证据）**：

| A2 正常列表 | ✅ 分组头 chevron + 计数右对齐、行 28px 逻辑高（行距 57 物理）、选中行中性叠加 | `shot-…601021` |
| A7 工具栏单行 | ✅ 搜索框 + 新增服务器（文字主按钮）+ 4 个图标按钮，一行放下（面板 785 逻辑点宽） | `zoom-tb2` |

**发现的缺陷（本轮已修，待你重启后复验）**：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| **D1** | 选中/悬停行上，「连接」和「⋯」**压在「已存口令」徽章上**，徽章文字被截断成「已存…令」 | `.att-row-actions` 绝对定位 + 渐变背景，但行的 `padding-right` 仍是 10px；徽章是 `flex: 0 0 auto` 排在最右，正好是按钮落点 | `.att-row` 右侧无条件预留 58px（`padding: 5px 58px 5px 10px`），去掉渐变背景 |
| **D2** | 「监控」图标在 16px 下读作**一顶帽子 + 一根斜线**，不像表盘 | `A5.8 5.8 0 0 1` 的 `large-arc-flag=0` 画的是 **140° 小弧**，不是想要的 220°；指针又短，融进了弧里 | 拆成两段 110° 子弧（`large-arc` 恒为 0，无歧义）+ 中心实心 hub + 加长指针 |

D2 的修法有本地预览图（用 Pillow 按同一组角度/半径重绘 16px 图形对比新旧），
旧图确认是「帽子」，新图是明确的三分之一缺口表盘。

**未验（被环境挡住，见下）**：

- 空态 / 搜索无结果（`zzz`）：需要键盘输入 → **未验**
- 焦点环、Tab 顺序、roving tabindex、右键菜单键盘：需要键盘 → **未验**
- 380 / 480 / 640 窄栏：需要拖动分隔条 → **未验**（当前只验了 785 逻辑点这一档）
- 浅色主题：需要切换宿主主题 → **未验**（当前是深色）
- 文件页上下文条、监控页 / HUD、对话框、确认框：需要点击切页 → **未验**

**为什么未验**：`mouse_click` / `type_text` 返回 `success:true` 但**零效果**，
`get_ui_tree` 直接在回包里写：

```
Accessibility permission is missing. Enable AT-PC Agent under
System Settings > Privacy & Security > Accessibility.
```

即 macOS 辅助功能授权没给到 `at-pc-agent-macos-arm64`。授权后（把该二进制加进
「隐私与安全性 → 辅助功能」）上面 5 条都能继续走完。屏幕录制是通的（截图正常、OCR 正常）。

## 11. 2026-10-18 第二轮：权限打通后的逐项走查

**通道换了两处，结论才有意义**（先说清楚，否则下一个人会重踩）：

1. **授权不是问题，责任进程才是。** 面板里 `at-pc-agent-macos-arm64` 的开关是开的，
   但从沙箱 shell 派生的 agent，`AXIsProcessTrusted()` 仍为 `false`。改成**由「终端」派生**
   （用户在 Finder 双击 `.command`）之后，`AXIsProcessTrusted / CGPreflightPostEventAccess /
   CGPreflightListenEventAccess` 三个都是 `true`。
2. **坐标空间不统一。** `crop` / OCR 行框是**物理像素**，`mouse_*` 要的是**逻辑点**。
   at-pc 的 schema 把后者也写成 `pixel`，于是"按字面调用"永远点不中（详见
   `at-pc/docs/testing/2026-10-18-macos-input-defects.md`）。本轮的鼠标坐标一律是
   `物理坐标 ÷ 2`。另外 hover 需要"先点一次"才能出效果（at-pc 的 drag/hover 状态机 bug）。

### 11.1 通过（有图为证）

| 项 | 结果 | 证据 |

### 13.3 D5（新缺陷）：会话标签标题被硬裁成 `家用n`，没有省略号

  读起来像一个**不同的服务器名**，而不是"被截断了"。

- **代码定位**：`styles.ts:922` 的 `.att-tab-title-text` 其实已经有
  `overflow:hidden; text-overflow:ellipsis; white-space:nowrap`。所以截断不是发生在我们的 span 上，

### 14.2 D8（新缺陷，已修）：查看器把 i18n key 印在按钮上

- **现象**：文件查看器工具栏的编辑按钮显示 **`sftp.fileEdit`**（OCR 实测宽 70px），不是「编辑」。
- **根因**：`views/sftpFile.ts:284` 调用 `t('sftp.fileEdit')`，而 `i18n.ts` 里**只定义过** `sftp.fileEditBlocked` 与 `sftp.fileEditorLabel` —— 这个 key **从来没存在过**。宿主对缺失 key 的 fallback 是返回 key 本身。
- **为什么门禁没抓到**：`copy-i18n.test.ts` 只比对 **zh 与 en 的 key 集合是否相同**。两边都缺同一个 key 时，它永远是绿的。这是「断言盯错载体」的又一变体：对**对称性**的断言被当成了对**完整性**的断言。
- **修法**：补 zh `编辑` / en `Edit`；`copy-i18n.test.ts` 新增一条**扫源码**的门禁：所有 `t('…')` 字面量必须在 zh 字典里存在（本轮实测 268 个调用 key / 350 个字典 key，**只有这 1 个缺失**）。反向测试：把 key 改名 → 该条与对称性那条同时 FAIL，已读回还原。

### 14.3 D9（新缺陷，根因待定）：方向键移动焦点，选中不跟随

- **现象**：资产列表点选 `99.92` 后按 ↓：焦点环正确前移（`99.92 → jenkins → 家用nas`），但**选中底始终停在 `99.92`**，行尾的 `▣ ⋯` 也跟着 `99.92`。鼠标移开后再按 ↑/↓ 复现同样结果 —— **已排除 hover 干扰**。
- **为什么是缺陷**：`assets.ts:247` 的注释明确写着 "Selection follows focus, which is what makes the shortcut and the row menu act on the row the user is looking at"。实际行为与注释相反：快捷键与行菜单作用的是**看不见的那一行**。
- **已排除**：`renderRow` 的 `onClick` 正确绑在行上并调用 `props.onSelect(server)`；`body.ts:894` 的 `onSelect` 直接 `setListSelectedId`；`selectedId` 与它同源。结构上没有第二份状态。
- **待查方向**（下一轮用诊断日志确认，不盲改）：`listNav.moveRowFocus` 里有 `node.focus()` 后紧跟 `node.click()`。焦点确实移动了，说明 handler 走到了这一行；若 `click()` 派发的合成事件被宿主在 capture 阶段丢弃（`isTrusted === false`），选中就不会变。另一种可能是状态被后续 effect 覆盖。
- **修复前的判断**：不用「加一条直接调用 onSelect 的分支」盲修 —— 那样即使表象消失，也说不清是哪条路径在起作用，而且与 `listNav.ts` 里刻意只用 click 的设计说明冲突。

### 15.2 D11（新缺陷，已修）：服务器列晒 UUID，把命令挤成 `$…`

- **现象**：折叠行显示 `4d1fbefc-aeef-42e9-90… · $ upt…`；第二条更糟，命令只剩 `$…`。
- **根因**：结果把目标写成 **id**，而 SSH 资产的 id 是 36 字符 UUID；`serverOf` 优先取结果的 `serverId`，
  `styles.ts` 给 `.att-tool-server` 的 `max-width` 是 160px —— 一行的宽度被一个**读者用不上的标识**吃掉了。
- **修法**：`displayServer()` 把 UUID 压成前 8 位 + `…`（`4d1fbefc…`，足以在一段对话里区分两台机），
  非 UUID（调用方直接传名字）原样显示；`.att-tool-server` 的 `max-width` 160px → **88px**，把宽度让给命令。
- **复验**：同一段对话重载后读作 `4d1fbefc… · $ uptime · exit 0 · 445ms` / `$ sleep 60; e… · signal unknown · 5.0s`。
- **已知取舍**：卡片只能拿到 id，拿不到资产名（agent 是先 `list_ssh_servers` 查到 `99.90` 再按 id 调用的）。
  8 位短形是当前 block 里能诚实地给出的最好形式；要显示名字得让工具结果带上 `serverLabel`，那是 Host 半的改动。

### 15.3 根因不在卡片：构建把 `'\n'` 改成了 `"\n    "`

第一次验收时两张卡的 `stdout` **都是**「（无输出）」，第二条连 `stderr` 分区都不出现 —— 系统性现象，不像解析写错。
逐层排除后，用一次性诊断探针（`postDiagnostic`）拿到铁证：

```
tool-card call_00_… textLen=135 out=so0/se0
  shape ["text:135:x"]
  head  "[4d1fbefc-…] exit 0 (445ms):\n```\n 11:03:41 up 466 days"
```

`text` 完整（135 字符、只有一个 text block），但解析出的 `stdout` 长度是 0。把同一段文本喂给同一份解析逻辑，
本地复算却**是对的** —— 于是问题只可能在**运行中的产物**里。对比源码与 `dsh/client.js`：

```
SOURCE:  body.split('\n')
BUNDLE:  body.split(`
    `)          ← 模板字面量的内容是「换行 + 4 个空格」
```

- **成因**：`esbuild` 开 `minifySyntax` 时，会把「含换行的字符串」打成**多行模板字面量**（省字节）；
  而 `dsh/esbuild.dsh.mjs` 的 `wrapClient` 为了满足 `verify.mjs` 的一条**逐行文本检查**（"第 1 列不许有语句"），
  给 bundle 的**每一行**加 4 空格缩进 —— 缩进落在模板字面量里，就成了字符串内容。
- **影响面（实测）**：全量包里 **12 处**空白多行模板字面量被污染，包括 xterm 自己的换行常量与
  `resultText` 的 `join('\n')`。这条 bug **早于 UI2-12**，只是此前没有任何东西依赖这些字符串的精确值。
- **修法（放弃启发式，改用行为验证）**：
  1. `wrapClient` **不再重排 bundle 的字节**；
  2. `verify.mjs` 的第 2 项检查从「扫第 1 列的语句」改为**结构断言**（loader 调用是第一条语句、只注册一次、
     结尾闭合），**纯净性由第 3 项在 VM 里执行证明** —— 沙箱只给 `window.__ModuleLoader__`，任何 DOM/网络/抛错都会失败。
     逐行扫描无法在不解析文件的前提下区分「语句」与「字符串内容」，这是它作为门禁的**原理性缺陷**，不是用法问题。
- **副作用**：`dsh/client.js` 从 1,085,922 B 降到 **1,011,391 B**（那 4 格缩进纯属体积）。
- **回归门禁**：`tool-call.test.ts` 新增两条**针对产物**的断言 —— 包里不得出现 `` `\n<空白>` `` 形状的模板字面量；
  `body.split` 必须切在裸换行上。反向测试：把产物里的 `body.split(`\n`)` 改回 `\n    ` → **两条同时 FAIL**，已重建还原。
- **教训**：为了让一条文本门禁通过而改写产物字节，代价是产物**不再等于源码的语义**。门禁宁可弱一点，
  也不能要求构建去动代码；真要强，就在 VM 里**执行**它。
