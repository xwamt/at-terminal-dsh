## 怎么用这份清单

- 计划里每个视觉任务（UI2-05…UI2-12）的 DoD 都引用本文档。**改动 ui 后按类走查**，只走受影响的行。
- 两类标注：
  - `[自动]` —— 静态断言能查（`className audit`、token 字符串、`em dash`/emoji grep）。PASS 只证明规则存在。
  - `[需真机]` —— 必须人眼在真实 dsh 里看。这份清单存在的主要理由就是这些项脚本查不了。
- **勾选框留空。只有真机看过才能勾。**
- 每一行都要写「怎么看」和「期望看到什么」——没有期望的勾选等于没看。

## 10. 2026-10-18 首次真机走查（at-pc 远程取证，`bdec116`）

**方法**：本机起 `at-pc-server` + `at-pc-agent`（device_id `atpc-ui-verify`），MCP 驱动
`list_windows` / `focus_window` / `capture_screen` / `read_screen_text`，窗口是
`at-terminal-dsh 界面优化建议 — DeepSeek Harness`（hwnd 21610，1472×820 逻辑点，scale 2.0）。

**证据图**（`docs/research/2026-10-18-ui-walkthrough-assets/`）：
`panel-top.jpg`（面板整体）· `toolbar-icons.png`（工具栏图标）· `tab-chip.png`（tab 图标）·
`d1-row-actions-over-badge.png`（D1 缺陷特写）· `d2-gauge-old-vs-new.png`（D2 新旧对比）。

**坐标口径（踩过，记下来）**：`list_windows.rect` 与 `get_ui_tree` 是**逻辑点**；
`capture_screen.crop`、`read_screen_text` 行框、`mouse_click` 期望的是**物理像素**——
乘 `scale_factor`。把逻辑点直接喂 crop 会截到左上角一块无关区域。

**已验（截图/OCR 证据）**：

| A2 正常列表 | ✅ 分组头 chevron + 计数右对齐、行 28px 逻辑高（行距 57 物理）、选中行中性叠加 | `shot-…601021` |
| A7 工具栏单行 | ✅ 搜索框 + 新增服务器（文字主按钮）+ 4 个图标按钮，一行放下（面板 785 逻辑点宽） | `zoom-tb2` |

**发现的缺陷（本轮已修，待你重启后复验）**：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| **D1** | 选中/悬停行上，「连接」和「⋯」**压在「已存口令」徽章上**，徽章文字被截断成「已存…令」 | `.att-row-actions` 绝对定位 + 渐变背景，但行的 `padding-right` 仍是 10px；徽章是 `flex: 0 0 auto` 排在最右，正好是按钮落点 | `.att-row` 右侧无条件预留 58px（`padding: 5px 58px 5px 10px`），去掉渐变背景 |
| **D2** | 「监控」图标在 16px 下读作**一顶帽子 + 一根斜线**，不像表盘 | `A5.8 5.8 0 0 1` 的 `large-arc-flag=0` 画的是 **140° 小弧**，不是想要的 220°；指针又短，融进了弧里 | 拆成两段 110° 子弧（`large-arc` 恒为 0，无歧义）+ 中心实心 hub + 加长指针 |

D2 的修法有本地预览图（用 Pillow 按同一组角度/半径重绘 16px 图形对比新旧），
旧图确认是「帽子」，新图是明确的三分之一缺口表盘。

**未验（被环境挡住，见下）**：

- 空态 / 搜索无结果（`zzz`）：需要键盘输入 → **未验**
- 焦点环、Tab 顺序、roving tabindex、右键菜单键盘：需要键盘 → **未验**
- 380 / 480 / 640 窄栏：需要拖动分隔条 → **未验**（当前只验了 785 逻辑点这一档）
- 浅色主题：需要切换宿主主题 → **未验**（当前是深色）
- 文件页上下文条、监控页 / HUD、对话框、确认框：需要点击切页 → **未验**

**为什么未验**：`mouse_click` / `type_text` 返回 `success:true` 但**零效果**，
`get_ui_tree` 直接在回包里写：

```
Accessibility permission is missing. Enable AT-PC Agent under
System Settings > Privacy & Security > Accessibility.
```

即 macOS 辅助功能授权没给到 `at-pc-agent-macos-arm64`。授权后（把该二进制加进
「隐私与安全性 → 辅助功能」）上面 5 条都能继续走完。屏幕录制是通的（截图正常、OCR 正常）。

## 11. 2026-10-18 第二轮：权限打通后的逐项走查

**通道换了两处，结论才有意义**（先说清楚，否则下一个人会重踩）：

1. **授权不是问题，责任进程才是。** 面板里 `at-pc-agent-macos-arm64` 的开关是开的，
   但从沙箱 shell 派生的 agent，`AXIsProcessTrusted()` 仍为 `false`。改成**由「终端」派生**
   （用户在 Finder 双击 `.command`）之后，`AXIsProcessTrusted / CGPreflightPostEventAccess /
   CGPreflightListenEventAccess` 三个都是 `true`。
2. **坐标空间不统一。** `crop` / OCR 行框是**物理像素**，`mouse_*` 要的是**逻辑点**。
   at-pc 的 schema 把后者也写成 `pixel`，于是"按字面调用"永远点不中（详见
   `at-pc/docs/testing/2026-10-18-macos-input-defects.md`）。本轮的鼠标坐标一律是
   `物理坐标 ÷ 2`。另外 hover 需要"先点一次"才能出效果（at-pc 的 drag/hover 状态机 bug）。

### 11.1 通过（有图为证）

| 项 | 结果 | 证据 |
