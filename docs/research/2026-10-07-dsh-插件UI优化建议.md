# DSH 插件 UI 优化建议 —— 官方规范梳理与对标分析

> 目标插件：`at-terminal-series` 的 dsh 变体（分支 `base-dsh`）  
> 调研日期：2026-10-07  
> 结论先行：**当前实现主题合规（11 个 token 全部真实存在、零硬编码色、零客户端包 import），但可访问性与"官方体感一致性"存在系统性缺口**——零 `aria`/`role`、零快捷键、零加载动画、零 `prefers-reduced-motion`。这些不是审美问题，而是官方规范里点名要求的项。

## 1. 官方约束梳理（5 类）

### 1.1 组件样式：唯一可共享的控件库，且明令禁止 import

`dsh-client-ui-primitives` 提供成套 React 原子组件（`README.zh.md`）：

- **控件**：`Button`（variant: `primary`/`ghost`/`outline`/`toolbar`；`md`=H36/R12、`sm`=H28/R8）、`Switch`、`SegmentedControl`、`Checkbox`、`Input`、`Menu`/`MenuItemButton`、`MenuGroup`、`Pill`、`SegmentedTabs`、`Tag`、`PathLabel`、`StateDot`、`ConnectionIndicator`、`DisclosureRow`、`TextShimmer`、`Modal`、`RiskConfirmation`、`Tooltip`、`HoverCard`、`ImageLightbox`、`Toast`
- **设置页**：`SettingsForm`、`SettingsValueField`、`SettingsSecretField` + `SettingsFormModel`
- **输出卡片**：`TerminalBlock`、`ReadBlock`、`DiffBlock`、`SearchBlock`、`WebBlock`、`JsonTree`
- **图标**：`icons/*`（`Regular`=1px / `Medium`=1.3px 双线重）、`FileTypeIcon`、`PluginArtworkTerminal`

**⚠️ 最关键的一条硬约束**（`references/practices.md`，UI 段第 3 条）：

> Do not `require('@deepseek-ai/dsh-client-ui-primitives')` or load any other Harness Client package as a module… **Write your own controls and match the host instead**: copy markup, CSS, and behavior from the primitive into the plugin… Rename copied classes under your plugin's prefix, keep only `--dsw-alias-*` token references, and keep the behavior that users rely on, such as **Modal focus and Escape handling, `role="switch"` with `aria-checked`, and Tooltip placement**.

**含义**：官方**堵死了 import 组件库这条路**（理由：这些包随时会变、纯 JS 插件无类型检查、组件抛错会让 slot 变空白），要求"抄源码 + 改类名 + 只留 token 引用 + 保留无障碍行为"。这直接决定了实现策略：**自写控件，但行为必须对齐 primitive**。

### 1.2 主题与配色：token 是唯一权威，禁止字面色

`dsh-client-ui-theme`（`README.zh.md` + `lib/client.js`）：

- 用户在「通用」分区选 `light` / `dark` / `system` + 正文字号 10–22px（默认 14）
- 宿主把 `ThemeSnapshot` 应用到文档；**第三方主题可经 `ctx.theme` 注册别名 token 覆盖**
- 首帧防闪：宿主在 index 响应里嵌入调色板，head CSS 在任何脚本运行前选定画布配色，body 脚本在应用脚本之前设 `body[data-ds-dark-theme]` 与 `--dsh-content-font-size`
- **实测 token 全集：403 个**（`--dsw-alias-*` / `--dsw-state-*` / `--dsw-menu-*` / `--dsw-elevation-*` / `--dsw-shadow-lv*`）

关键机制（`lib/client.js` 与 `ui-theme` README 交叉确认）：

| 机制          | 细节                                                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 焦点环         | `--dsw-focus-ring-color`（浅色 `#4176E6` / 深色 `#7AAAFF`）、`--dsw-focus-ring-width`（标准 2px，密集表格/工具栏可 1px）；**不声明 outline 样式**        |
| 指针模态        | `html[data-input-modality='pointer']` 下焦点环透明；`data-shimmer-decoration` 标记参与扫光                                                  |
| 圆角          | `corner-shape.css` 在 `@supports (corner-shape: superellipse(1.5))` 内平滑所有圆角；正圆与胶囊**必须**配对 `corner-shape: round`                 |
| 滚动条         | 5px `--dsh-scrollbar-width`，`design-platform.css` 先于 `scrollbar.css` 加载；高层级表面重绑为 l2 token；`ui-sidebar` 指针不在栏内时重绑 `transparent` |
| Token 是唯一权威 | 官方原话：设计系统中缺失的值**有意不补入**，一律采用最接近的语义 token                                                                                       |

> **对插件的直接约束**：`practices.md` 明确「literal colors are for artwork only」。插件若绕过 token 自造颜色，浅色/深色切换时会失配。

### 1.3 扩展机制：Slot 声明即认领 + 渲染面决定样式上限

`dsh-client-ui-slots` + `practices.md`：

- 四种 kind：`single` / `list` / `keyed` / `chain`
- **声明纪律**："声明即认领"——注册条目成为唯一被允许渲染该键的条目；重复声明、跨 scope 挂同一句柄、chain 缺 `select` 都会在**加载时抛出**
- **贡献方式**：`ctx.slots.inject(ownerKey, () => ctx.slots.register(...))`；回调内注册随宿主声明收起/恢复而销毁/重装
- **五个框架 props share**（运行时 / child render / factory render / store / 业务）由类型推导，**插件不得本地重定义 share 类型**
- 铁律（`ui-plugin.md`）："Do not read another plugin's DOM, stylesheet, or component source to estimate placement; choose a slot that already allocates space."
- 铁律（`practices.md` 第 6 条）：**"Plugin UI is part of the Harness UI… Whether that is possible is decided by where the UI renders, so choose the rendering surface before writing any view; later styling inside the wrong surface cannot recover consistency."**

> 官方对 UI 插件的**根本要求是"看起来像同一个应用"**，而非"做出一个功能面板"。

### 1.4 本地化与配置

- `practices.md`：可调值放 `Config`，用户在 `cordis.patch.yml` 改，**用户补丁层能在升级中存活**
- `ui-plugin.md`："Route visible UI text through the Client locale service"
- `ui-primitives` 已知限制原文：原子组件**拿不到 `ctx.locale`**，每段文案必须通过 label prop 提供，**遗漏会导致类型检查失败**——即"漏翻"是编译期可抓的错误
- 我们已用 `ctx.locale.register(NS, {zh, en})`（`dsh/client.js:12382`）✅

### 1.5 快捷键与可访问性

- 存在 `dsh-client-ui-shortcuts` 服务；`ui-plugin.md` 要求经 `dsh.client.inject` 排序激活
- 官方 tab 命令约定（`sidebar-files` / `sidebar-terminal`）：命令 + 平台默认键（Windows/macOS Web 用快捷键服务默认值，**Linux Web 默认不绑定**）+ **开始页入口显示有效快捷键的无背景文字，不额外弹重复提示**
- primitive 层的无障碍硬要求：`Switch` 必须有 `label`（"控件不可能在没有名称的情况下发布"）、`role="switch"` + `aria-checked`、Modal 的 Esc/Tab 焦点管理、Tooltip 的 `focusDelayMs`

## 2. 对标案例（4 个官方插件 + 1 个行业参照）

### 案例 A：`dsh-client-ui-sidebar-files`（最贴近——同为文件树）

**视觉风格**：共享 `FileTypeIcon`（28px，按类别着色）、`PathLabel`（目录弱化色 + 文件名主色）。  
**布局层次**：strip 标题行 → 根路径 → 树 → 右端 actions；正文贴边，右侧预留 **2px 滚动条间距**。  
**信息密度**：行序 = **目录优先 → 自然序不分大小写**；dotfiles 与其他条目一样显示（不特殊隐藏）。  
**状态反馈**（最值得抄）：

- 被端点条目上限截断的层 → **一条标记收尾**，不静默截断
- 空层 → **如实说明**
- 失败的层 → **按错误码各显示一行**（`workspace-file/not-found` / `outside-workspace` / `not-directory`），其他情况显示传输层自己的消息
- 无工作目录的会话 → 只显示一行说明，**而不是树**  
  **易用性**：命令 `workspace.files`，桌面默认键 Mod+P；开始页入口显示快捷键；存储按 tab id 分桶，切走再切回**带着已加载的层重新挂载、滚动位置恢复**。

### 案例 B：`dsh-client-ui-sidebar-terminal`（同为我方要复刻的终端）

**状态反馈**：

- 暂时断线 → **保留屏幕**并提供「重新连接」，**不展示传输内部错误**
- 已退出的 shell → 仍显示**退出码**并提供「新建终端」，**不会自动重启**
- 恢复时保存的进程已消失 → 本地化不可用提示 + 「新建终端」，**恢复过程不自动创建替代进程**
- 其他页面持有输入权时 → 点「**接管输入**」使当前连接可写

**可访问性硬标准（本报告最重要的一条量化依据）**：

> xterm 将文字对比度调整到 **4.5:1**；光标与所在单元格背景保持至少 **3:1** 的对比度，包括 Vim 配色方案。

**主题**：终端背景、默认文字、光标和选区跟随 DSH 主题（含系统偏好与令牌覆盖）；**切换主题会保留运行中的 shell、输出和应用通过 OSC 设置的颜色**；颜色重置命令恢复到当前 DSH 默认值。

**布局**：正文在 tab 条下方预留 **8px** 间距；xterm 与 FitAddon **不进启动 `client.js`**，挂载时才加载 chunk。

### 案例 C：`dsh-client-ui-sidebar-documentpreview`（加载/失败态范式）

- 首次读取及渲染共用**居中 28px ongoing `StateDot`**，下方本地化状态文字（"文档渲染中…"），**状态向辅助技术提供相同名称**，并遵循减少动态效果偏好
- 追加文本页时用**紧凑行内转圈**，同时保留已显示内容
- 失败时：正文填满**文件类型图标 + 说明 + 该失败对应的出路**（重试 / unpreviewable 子 slot / 什么都不给）
- **较晚的失败保留已有内容并在其下提供重试**（不清空已渲染）
- 只有一个渲染器时**不显示查看器控件**；仅当渲染器声明 `wrap: true` 才显示换行开关

### 案例 D：`dsh-client-ui-sidebar-documentpreview` 的表格渲染器（主题一致性细节）

> 表格控件在应用的明暗两种主题下均保持**浅色背景和深色文字**。

这是一条**有意的例外**，说明"跟随主题"不是无脑反转——表格类控件需要固定浅底。

### 案例 E：行业参照（VS Code 变体，即本项目自己的 `base` 变体）

`at-terminal` 的 VS Code 版已实现服务器表单、资产导入导出、终端与 SFTP 完整交互。**它是最省力的对标源**：`dsh` 变体的 `styles.ts` 已建立 `--vscode-*` → `--dsw-alias-*` 桥接层（26 个变量），使两张 CSS 表可共用。但**当前只覆盖两张表读到的变量**，不是完整映射。

## 4. 优化建议（按优先级）

### 🔴 高优先级

#### H1. 补齐终端与 SFTP 的无障碍语义（`aria` / `role` / 焦点）

- **问题现状**：`src/platform/dsh/client/` 全域 `aria-*` 与 `role` **零命中**。`views/sftp.ts` 的可展开目录行是纯 `div` + 点击回调，键盘用户无法展开；`switcher` 类控件（信任主机、允许 sudo 回退）无 `role="switch"` + `aria-checked`。
- **改进方案**：
  1. 可展开行改 `role="treeitem"` + `aria-expanded` + `tabIndex=0` + `onKeyDown`（`Enter`/`Space` 展开收起、`↑`/`↓` 移动、`→`/`←` 展开收起），容器 `role="tree"` + `aria-label`；
  2. 二元开关补 `role="switch"` + `aria-checked`（官方 `Switch` 的硬要求）；
  3. 工具栏图标按钮补 `aria-label`（i18n 走 `NS` 命名空间）；
  4. 弹窗复用 primitive 的 Esc/Tab 焦点管理：容器 `tabIndex={-1}`、初始控件打 `data-modal-autofocus`、关闭归还触发元素焦点。
- **预期收益**：键盘可完整操作 SFTP 树与开关；官方规范明列的行为对齐项，从"能跑"升级为"合规"。**成本低**（纯属性 + 少量 handler）。

#### H2. 注册并展示快捷键

- **问题现状**：零快捷键。用户切页只能点 tab 条；服务器列表 ↔ 文件页 ↔ 终端页之间无快捷路径。官方 `sidebar-files`（Mod+P）与 `sidebar-terminal`（`terminal.new`）都有命令 + 键位。
- **改进方案**：
  1. 经 `dsh.client.inject` 接入 `dsh-client-ui-shortcuts`，注册三条页内导航：`列表` / `文件` / `终端`，用 `mod+P` 风格键位（macOS 用 Cmd、Linux 走官方默认值不绑定）；
  2. 在 tab 类型标题行与开始页入口按官方做法显示**有效快捷键的无背景文字**，不另弹重复提示；
  3. 保留输入框聚焦时的按键透传（终端页尤其重要——Ctrl+C 等不得被面板快捷键截走）。
- **预期收益**：三页切换零成本；与官方 tab 体感对齐。

#### H3. 加载态与动效降级

- **问题现状**：`assets.ts:127`、`dialogs.ts:151/243` 的 pending 态是纯文字行（`att-line`）；`styles.ts` 里 `@keyframes` **0 个**，唯一的 `@media` 逻辑是 CSS 解析器自身的（`styles.ts:61`），**无任何 `prefers-reduced-motion`**。长列表读取时界面看起来"卡住了"。
- **改进方案**：
  1. pending 态加**居中 14px ongoing 旋转点**（复用官方 `StateDot` 的几何：10px 槽、tertiary 灰、动画锚定文档时间零点使多个 loading 同相），下方保留本地化文字；
  2. SFTP 树按目录粒度做骨架占位（官方是"折叠期间保留已显示条目缓存"，我们已有缓存，可直接复用为占位）；
  3. **新增 `@media (prefers-reduced-motion: reduce)`**：把旋转点换成静态琥珀/中性点、扫光改为静态底色（官方 `TextShimmer` 的约定："减少动态效果模式保留静态底色"）；
  4. 加载超过 300ms 才显示（避免快读时闪烁）。
- **预期收益**：等待可感知；动效降级同时满足官方要求与可访问性。

#### H4. 终端对比度达标（4.5:1 / 3:1）

- **问题现状**：官方终端侧栏明文规定"xterm 将文字对比度调整到 4.5:1；光标与所在单元格背景至少 3:1，包括 Vim 配色方案"。我们的 `xtermEngine.ts` 跟随 token 但**未见对比度校正**，也未处理用户 Vim/tmux 自定义配色。
- **改进方案**：
  1. 在 `xtermEngine.ts` 挂载后读取 `--dsw-alias-*` 解析出的实际前景/背景，按 WCAG 相对亮度公式算出比值；低于 4.5:1 时**调整前景或背景**（优先改背景，因为前景承载 ANSI 语义色）；
  2. 光标单独保证 ≥3:1；
  3. 提供"尊重用户配色"开关：用户自设 ANSI 配色时**只校验不强制改写**，但对比度不足时显示一次性提示（对齐官方"不展示传输内部错误"的克制——告知而非阻断）。
- **预期收益**：这是官方唯一给出**数值**的可访问性标准，也是终端可用性的底线（低对比度在亮色主题下会看不清）。


### 🟡 中优先级

#### M1. 扩充 token 覆盖（11 → 40+）

- **问题现状**：仅用 11 个 token，导致大量 VS Code 变量只能停在 `TOKEN_BRIDGE` 那一层间接映射；`--dsw-alias-switch-thumb`、`--dsw-alias-toast-bg`、`--dsw-alias-focus-ring-color`、`--dsw-alias-bg-skeleton`、`--dsw-alias-interactive-bg-hover` 等语义 token 都没用上。
- **改进方案**：
  1. 把 `TOKEN_BRIDGE` 从"两张表读到的变量"扩成**显式设计映射表**，每条注明对应官方 token 与用途；
  2. **把 26 个 `--vscode-*` fallback 值从深色改为"双主题对"**——当前 `#181818` / `#252526` / `#1e1e1e` 全是深色主题值，一旦 token 改名（官方明说会"降级但不破版"）浅色模式会得到黑底深字。fallback 应改为 `light-dark()` 或直接省略（让 token 缺失显形，而非静默错色）；
  3. 优先补齐语义类：`state-*`（success/warn/error/info）、`interactive-bg-hover*`、`bg-skeleton`、`label-caption`、`border-l3/l4`。
- **预期收益**：抗 token 重命名；语义 token 自带状态色，减少自己判断"成功该用绿还是琥珀"。

#### M2. SFTP 树的失败分层显示（对齐 `sidebar-files`）

- **问题现状**：有 `disconnected` 横幅与 `noTerminal` 空态（这部分**做得好**，是现有亮点），但**单个目录读失败**时行为未核实到"按错误码逐行显示"。
- **改进方案**：
  1. 失败层按 code 分别渲染：`sftp-no-such-file` / `sftp-permission-denied` / `sftp-read-failed` 各配一句本地化说明（`§0.26.2` 已把这三个码做出来了，只差 UI 分层）；
  2. **单层失败不清空兄弟层与根**（与官方"较晚的失败保留已有内容并在其下提供重试"同构）；
  3. 被截断的目录加一条收尾标记（对齐官方"截断层以一条标记收尾"）。
- **预期收益**：用户能区分"目录读不到"与"目录是空的"——这正是 §0.26.2 第 2 条修复的成果，UI 层还没把它表达出来。

#### M3. 补充 tab definition 字段与恢复能力

- **问题现状**：`dsh/client.js:12364` 只有 `id`/`kind`/`title`/`guide`。缺 `patterns`（不认领资源地址）、缺官方 tab 的档位标注、缺 actions slot。
- **改进方案**：
  1. 补 `patterns`（明确本 tab **不**认领 `dsh-resource://file/**`，避免与 `files` tab 抢）；
  2. 复用官方 `sidebar.right.tab.files.actions` 这类 Session 作用域子 slot 承载"在 Finder/文件管理器打开"；
  3. 正文加**标题行**（官方 files tab 用共享 `PathLabel` 显示根路径：目录弱化色、文件名主色、溢出保留尾部并在左侧渐隐、悬停显示完整路径）——我们的状态栏已有 `max-width:40%` + ellipsis，可直接升级为 PathLabel 行为。
- **预期收益**：与官方 tab 行为一致；路径可读性提升。

#### M4. 引入共享图标（`FileTypeIcon` / `icons/*`）的自绘版本

- **问题现状**：零官方图标。终端页与文件树的行首标识缺失，识别度低。
- **改进方案**：按官方规则**自绘**（不得 import）：从 `dsh-client-ui-primitives/lib/index.js` 取 SVG 几何 → 复制到 `src/platform/dsh/client/icons/`，类名加 `att-` 前缀，只保留 `--dsw-alias-*` 填充；线重按 `Regular`(1px) / `Medium`(1.3px) 成对导出。优先补：文件夹、文件、终端、服务器、错误/警告三角、刷新。
- **预期收益**：视觉语言与宿主统一；目录/文件/终端一眼可辨。

#### M5. 暗色模式**真机验证**并加自动化守卫

- **问题现状**：代码零 `prefers-color-scheme` / `data-ds-dark-theme` 引用——**这是正确做法**（token 自动适配），但也意味着**浅色模式从未被验证过**。所有 fallback 值都是深色值。
- **改进方案**：
  1. **人工**：重启 dsh，在浅色与深色下各走一遍 SFTP 树 + 终端 + 服务器表单（浅色是主要风险面）；
  2. **自动化**：把"token 桥接层不得出现裸字面色"写成门禁第 9 项——扫描 `styles.ts`，`--vscode-*` 声明的值若不是 `var(--dsw-*)` 且不是 `color-mix` 包裹即 FAIL；
  3. 门禁须做**反向测试**（塞一个 `#ff0000` 裸色进桥接层，确认它 FAIL）。
- **预期收益**：把"未验证"变成"有守卫"。符合铁律二：没做过反向测试的脚本不算门禁。

### 🟢 低优先级

#### L1. 滚动条与圆角的宿主一致性

官方 `scrollbar.css` 约定：高层级表面（菜单/浮层/对话框）在自己容器上把 `--dsh-scrollbar-thumb` 重绑为 l2 token；`corner-shape` 超级椭圆需与正圆配对 `corner-shape: round`。我们的 `att-menu`（`styles.ts:240` 有 `position: fixed; z-index: 1000`）应重绑滚动条 token。

#### L2. 表格类控件的浅底例外

若服务器列表将来引入表格化视图，参考官方表格渲染器：**明暗两种主题下均保持浅色背景 + 深色文字**，不要跟随主题反转。

#### L3. 空态文案的操作化

官方 `documentpreview` 的失败态 = 图标 + 说明 + **对应的出路**（重试/子 slot/不给）。我们现有空态文案准确（这是 §0.26 的成果），但多数只"说明"没有"出路"。给"无终端"空态补一个「新建终端」动作、`disconnected` 补「重新连接」，与官方终端侧栏一致。

#### L4. 品牌字体仅用于品牌文字

`--dsw-font-family-brand`（Montserrat 300/400/500）**只给品牌文字**；普通界面用系统字体栈。我们桥接层的 `--vscode-font-family` 已用系统栈 ✅，保持。
