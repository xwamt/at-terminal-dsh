# AT Terminal (DSH) 0.3.0 Release Notes

## Summary

Version 0.3.0 is the **semantic-seam hardening** release: the Host service layer, the Agent tool
contracts and the browser client are brought into line with the installed Harness, and the gaps the
live runs exposed are closed. It adds **background jobs and job control**, **spilled results**, a
**settings page with a trust library**, **read-side deadlines**, a **registry-level authorization
seam**, **multi-server target safety**, **large-file `localPath` streaming upload**, and — for the
first time — a **second, opt-in package**: persistent SSH terminals.

Both npm packages ship in lockstep at `0.3.0`; they are not independent (the optional bundle
references the plugin's SSH backend by subpath).

46 commits, 128 files changed (+43,380 / −19,173) since `v0.2.0`.

## Highlights

- **Background jobs & job control** — `at_terminal_run_remote_command` accepts `run_in_background`
  and returns a job id that survives the turn; the model collects it with `at_terminal_job_output`
  and stops it with `at_terminal_job_kill`. Killing kills the remote process group; a kill that
  fails still leaves an audit row.
- **Spilled results** — a result too large to inline is written to a file and returned as a
  `spillPath`, read back in offset/limit slices instead of flooding the transcript.
- **Settings page, trust library & i18n** — a settings tab contributed into the host shell:
  authorization decision stats, the retained audit rows, and the saved SSH **trust library**
  (`SHA256:` fingerprints, comparable to `ssh-keygen -lf`, with per-server "forget"). Approval
  dialogs follow the system language.
- **Optional persistent SSH terminals** — a new package `@at-series/dsh-at-terminal-ssh` adds a
  `type: "ssh"` backend to the harness's own `ctx.terminals`, so the six built-in `terminal_*` tools
  drive a remote shell that survives between calls. Composed as an isolated `cordis:group`, so a
  profile without it is unaffected.
- **Multi-server target safety** — with several servers connected, write/execute tools refuse to
  guess the target: a missing `serverId` errors and lists the candidates instead of writing to the
  wrong host. Read tools still follow the active terminal but report `resolvedBy` / `candidates`.
- **Large-file `localPath` upload** — `at_terminal_sftp_write_file` accepts a host-side `localPath`;
  the host reads and streams the file to the remote, so a large binary never enters the model
  context (7.3 MB in ~470 ms, byte-identical sha256).
- **Read-side deadlines** — every tool declares a `timeoutMs`; SFTP read/list/stat carry a 30 s
  deadline and a dedicated `read_timeout` audit code, so a stalled channel fails instead of
  returning an empty-looking result.

## Added

- **Background execution & jobs**: `run_in_background` on the remote-command tool; a job registry
  with `at_terminal_job_output` / `at_terminal_job_kill`; pidfile written for tracked processes;
  jobs survive a turn and are reaped by the host registry.
- **Result spill**: `dsh/spill.js` plus a `spillPath` contract on oversized tool results.
- **Registry-level authorization**: `dsh/policy.js` and a `guard` + `tools/pre-execute` seam that
  decides once at the registry instead of inside each tool; a single approval-copy source and
  shared `authorizeCommand()`.
- **Prompt section & runtime skills**: the tool rules are stated once in a prompt section (tool
  definitions shrink ~45%); three runtime skills (inspection / remote-edit / incident-log) with a
  status line that admits when they did not land.
- **Settings page** (`settingsTab.ts`): decision statistics, retained audit rows, and the trust
  library of saved host keys; per-section cards; install / enable / disable the optional shell from
  the panel.
- **i18n**: approval dialogs and the panel copy follow the system language (English / 简体中文),
  through `src/i18n/copy.ts` and a `zh-CN` locale.
- **Optional bundle** `@at-series/dsh-at-terminal-ssh`: an SSH backend for `ctx.terminals`
  (`terminalBackend/sshBackend.ts`, `terminalEntry.ts`), composed as an isolated group; "one
  platform per process" so the SSH backend can actually open.
- **Multi-server target resolution** (`serverTarget.ts`): writes/executions require an explicit
  `serverId`; reads report how the target was resolved.
- **Timed SFTP write grants**: three grant durations so "15 minutes" stops silently meaning "once".
- **Channel fencing**: the mutating channel routes are fenced the way the Harness fences its own
  `/api`.
- **Real audit trail**: `agent-audit.jsonl` records both halves (read + write); history carries its
  provenance; the hardware probe is no longer mislabelled as a policy-cleared command.
- **Client performance**: xterm split into a load-on-demand chunk (entry bundle ~1 MB → ~413 kB) and
  the stylesheet split into its own chunk.
- **Monitor HUD**: the capsule drags by its six-dot grip; `open_monitor` supports `mode: "tab"`;
  a failed probe marks the reading stale instead of showing it as current.
- **Slash commands**: two commands answer without spending a turn.
- **Release tooling**: `scripts/release.mjs` ships both packages in lockstep (pairing check + gates);
  `verify-kernel-seam.mjs` makes the kernel gate real.

## Changed / Improved

- Settings: dead switches removed; the switch that matters is now real.
- Direct tools: honest capability list (17 tools), argument validation on every tool, bounded
  hardware metrics output.

## Fixed

- `~` is expanded before SFTP sees a path; the pty stream is kept plain text.
- `open_monitor` no longer claims a window nobody will see.
- The HUD capsule drag now actually moves the capsule.
- Latent-defect sweep: ten real defects across both halves (incl. a split character, a dead-end
  hint and a silently-skipped plan surface).
- A background job's pidfile is written (it was named but never written); a kill that fails leaves
  an audit row so its absence means something.
- README / `dsh/README.md` host-version claims re-synced to the installed Harness.

## Upgrading

- `link:` installs (this machine): `npm run build`, then restart DeepSeek Harness so the Host half
  reloads `dsh/tools.js`; a page refresh is enough for the client bundle.
- Other machines: install the tarball(s), or `npm install --save-exact @at-series/dsh-at-terminal` and
  optionally `@at-series/dsh-at-terminal-ssh`.
- The plugin tarball does not include `ssh2` (resolved from the repository's `node_modules` at
  runtime) or the build/verify scripts under `dsh/scripts/`.
