# AT Terminal (DSH) 0.3.1 Release Notes

## Summary

Version 0.3.1 is the **DSH 0.2.2-rc.1 compatibility and reliability** release. It closes the
remaining packaging and hot-reload gaps against the installed Harness, adds **remote SFTP
editing with stale-version protection**, an optional **multi-file `apply_patch`** tool, moves the
panel onto the Harness's native **context menus / file actions**, improves the **SFTP
tree + preview split layout**, and fixes **idle-disconnect cleanup** so a timed-out terminal no
longer leaves its SFTP and agent SFTP connections alive on the server.

Both packages ship in lockstep at `0.3.1`: the main plugin
(`@at-series/dsh-at-terminal`) and the optional composition bundle
(`@at-series/dsh-at-terminal-ssh`). The bundle resolves the plugin's SSH backend by subpath, so
publishing one without the other is not a release.

## Highlights

### DSH 0.2.2-rc.1 compatibility and packaging

- Vendored `@deepseek-ai/schemastery` **3.19.0** and `@deepseek-ai/cosmokit` **1.9.0**, matching
  the installed Harness.
- Declared `engines.node >= 24.9`, the DSH version range, and `dsh.manifestVersion: 1`; these are
  now enforced by `verify:dsh`.
- The npm package now includes all runtime modules (`jobs.js`, `locale.js`, `optionalBundle.js`,
  `policy.js`, `prompt.js`, `skills.js`, `spill.js`) and declares `schemastery` / `cosmokit` as
  bundled dependencies. `npm pack` is part of the release gate, so a registry install cannot
  silently miss a module.
- Platform teardown returns the real async `handle.close()`, deferred assembly is cleaned up,
  and `dialogLanguage` changes now travel through `loader/volatile-update` without remounting.
- `client.hello` is retained across plugin hot reloads, so a healthy panel no longer reports
  `clientHellos=0`.
- The optional bundle reports activation failures and pending builds, with a retry path in the
  settings page.

### Remote editing and write safety

- **`at_terminal_sftp_edit_file`** — replace one literal string in a remote UTF-8 file. The
  needle must match exactly once unless `replaceAll: true`; CRLF/LF style is preserved; binary
  and files over 2 MiB are refused.
- **`sftpWriteGuard`** (`off` / `observe` / `strict`, default `observe`) and
  `expectedSize` / `expectedModifiedAt` protect against overwriting a file that changed after
  the agent read it. `strict` additionally requires a prior read on the same connection.
- **`at_terminal_sftp_apply_patch`** (optional, `enableApplyPatch`, default `false`) — apply a
  Codex-style Add/Update/Delete/Move patch across multiple remote files. The whole patch is
  parsed and preflighted before any write; each operation reports `completed` / `failed` /
  `unknown` / `skipped`.
- Job tools are conditionally registered: the host's `job_output` / `job_kill` are used when
  present, and the plugin's `at_terminal_job_*` fallback appears only in compositions without
  them. Timeout and kill semantics remain explicit.

### Panel and SFTP UI

- Native `ctx.contextMenus` integration for the asset and SFTP trees, with the old local fallback
  retained for older hosts.
- Native `ctx.fileActions` download/save with a `saveBytes` fallback.
- SFTP preview now uses a **tree + preview split** at panel widths ≥ 560 px, with the
  终端/文件 navigation in a page-wide header above the split rather than inside the file pane.
- Added live diagnostics for context-menu opens, download outcomes, split-layout tier changes,
  and preview opens, so panel behaviour is verifiable from a real session instead of only from
  bundle tests.

### Idle disconnect now releases the whole connection chain

- `SshSession` now emits a single **`closed` lifecycle event** for every way an open session can
  end — idle timeout, remote close, or explicit dispose — in addition to the display status.
- The DSH terminal service forwards that event to `DshTerminalObserver.closed()`, so the
  terminal registry and the SFTP tree no longer keep a dead terminal marked as connected.
- `SftpAgentService` now listens to `onDidChangeContext` (the event the host actually fires on
  `markDisconnected`) and disposes the pooled agent SFTP session for that terminal. Previously
  it listened only to `onDidRemoveContext`, which the DSH path never emits, leaving an
  `sshd: root@notty` / `sftp-server` process alive indefinitely after a terminal closed.
- `idleDisconnectMinutes` still counts terminal input/output, not operating-system idle time;
  `0` disables the timeout.

## Added

- `at_terminal_sftp_edit_file` and the `sftpWriteGuard` / `expectedSize` / `expectedModifiedAt`
  version guard.
- Optional `at_terminal_sftp_apply_patch` with vendored `@deepseek-ai/dsh-fs-patch` parser
  (MIT / Apache-2.0 attribution in `src/sftp/patch/LICENSE` and `NOTICE`).
- Native context-menu and file-action integrations for the assets and SFTP surfaces.
- SFTP tree + preview split layout and the associated live diagnostics.
- Optional bundle activation diagnostics (`pendingBuilds` retry) in the settings page.
- `closed` lifecycle event on `SshSession`; terminal-bound SFTP cleanup in `SftpAgentService`.

## Changed / Improved

- npm packaging now ships all runtime modules with bundled `schemastery` / `cosmokit` and a
  `npm pack` release gate.
- Hot reload keeps the `client.hello` presence count and applies `dialogLanguage` volatile
  updates in place.
- Tool registration is server-gated; the prompt section follows the visible tool set, and the
  array-shaped `toolSet` case is handled correctly.
- SFTP preview navigation moved out of the file pane's toolbar in the split layout.

## Fixed

- Idle terminal timeouts no longer leave the terminal registry, SFTP tree, or agent SFTP pool
  pointing at a dead session; server-side `sftp-server` child processes are closed.
- `clientHellos` is no longer reset by every plugin hot reload.
- The prompt section no longer disappears when `toolSet` is an array.
- npm package omissions that would have produced `ERR_MODULE_NOT_FOUND` for registry users.
- Deferred platform assembly and plugin disable/re-enable no longer leave `at_terminal_state`
  reserved (`already-open`).

## Upgrading

- `link:` installs (this machine): `npm run build`, then restart DeepSeek Harness so the Host
  half reloads `dsh/host.bundle.js`; a page refresh is enough for the client bundle.
- Other machines: install the tarball(s), or `npm install --save-exact @at-series/dsh-at-terminal`
  and optionally `@at-series/dsh-at-terminal-ssh`.
- The plugin tarball does not include `ssh2` (resolved from the repository's `node_modules` at
  runtime) or the build/verify scripts under `dsh/scripts/`.
